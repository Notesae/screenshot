# 便携版更新（0.4.7 开发候选）

本批基于已发布 v0.4.6 的 `3d82dea536fbe6234eb748eb85ad177161120ae5`。版本号仅标记开发候选；本 PR 不创建 tag、不合并、不发布新版本，也不覆盖正在使用的安装。

## 当前可交付范围

原生设置窗口增加「应用更新」页签：当前程序集版本、稳定版/包含预发布通道、手动检查、最新版本及纯文本说明、下载进度、取消和重新下载、校验后安装、并排导出、旧版回滚。编辑器不接触更新路径、网络认证或进程启动能力。

仅用户点击检查/下载才访问固定的 `Notesae/screenshot` GitHub Release API 和该发布的 Windows x64 ZIP；没有自动检查、任意 URL 导入或网页按钮替代安装。通道仅在当前设置会话内生效，稳定通道同时排除 API 标记的预发布和 SemVer 预发布。按 SemVer 而非发布时间比较，检查和执行阶段都拒绝降级与重复安装；只有明确回滚操作可以恢复旧版。

## 私有源：仍未启用远程私有获取

已通过连接器只读确认仓库为 private。安装端匿名 API 请求会受限，不能借用开发环境的连接器授权。401/403/404 显示可操作错误，不声称已是最新版，不自动切换来源。未读取/复制开发机凭据，未嵌入 token，未创建 OAuth/API Key，未改变仓库权限或公开制品。

用户在本任务中选择后续采用**用户登录授权**，需另行批准实施。最小后续决定是批准一个归属 Notesae 的 GitHub 登录应用及其回调/设备登录方式，并确认账号应有的仓库只读权限和撤销体验。当前仅保留匿名官方源适配及可注入的 HTTP 测试边界，未新增登录界面或模拟登录成功。

建议后续方案：由原生宿主完成 GitHub 授权、每位用户显式登录自己的账号，权限限制在读取官方仓库发布所需范围；凭据仅由宿主通过当前 Windows 用户保护保存。原生传输仅给固定 GitHub API 加认证，资产 CDN 重定向剥离认证；前端仅获登录状态和公开版本信息。应覆盖拒绝授权、无仓库权限、过期、撤销、退出登录、代理与限流。新增应用注册或授权流程必须先获用户后续批准，不能把本设计当作批准。

依据：[GitHub Release API](https://docs.github.com/en/rest/releases/releases#list-releases)仅公开资源允许免认证访问，细粒度访问需 Contents read 权限。

## 完整性与安全边界

- 官方 API 必须提供 `sha256:` 资产摘要和合理长度；包名、版本、仓库及 HTTPS 地址严格匹配。缺失摘要、错误长度或 SHA 不匹配一律拒绝。下载有总时限、读取闲置时限和大小上限，取消/失败移除本次部分包，已有文件不被覆盖或误删。
- 禁用 HTTP 自动跳转和 Cookie；每跳仅接受 `release-assets.githubusercontent.com` / `objects.githubusercontent.com` 的 HTTPS 标准端口。不发送 Authorization。来源域发生变化时失败关闭，需审查后更新白名单。
- ZIP 文件数、单文件和总解压大小有上限；拒绝路径穿越、绝对路径、ADS、Windows 设备名、尾部空格/点、大小写重复和链接。检查目录祖先重解析点。
- 解压后核对包内 SHA256SUMS 全覆盖及必要文件、SBOM 版本，执行替换前重新核对暂存与旧目录摘要。安装目录含清单外文件时拒绝整目录替换，保留用户文件并提供解压到新目录。

API 摘要、包内清单均为完整性检查，**不构成发布者数字签名**。当前信任 GitHub 官方仓库账号、API 和 HTTPS；无法抵御发布账号或同一 Windows 用户权限遭入侵。没有伪称 Authenticode、独立签名或供应链认证。

## 退出后替换与恢复

1. 下载先放 GUID 临时目录；通过包校验后才开放安装。跨进程文件锁防止同一用户对同一目标并发更新，UI 也禁止重复操作。
2. 安装前明确提示保存、退出与重启。在安装目标的同级 `.screenshot-update-<guid>` 中复制已验证新包与当前完整运行时，预估安装盘空间；用户数据目录不得与目标重叠。
3. 从模态设置窗口取得当前 React 文档、修订和身份。其他本地/AI 任务、画布加载或文字编辑尚未完成时拒绝。使用独立恢复身份写入本机 SQLite 恢复库，避免相同修订被当作过期写入；失败保持应用打开。重启后由用户从恢复记录继续，不自动打开私人内容。
4. 启动隔离目录中的旧版辅助进程；它不初始化条款窗口、WebView、托盘、热键或截图。辅助进程确认就绪后主程序才写入交接确认并退出。确认失败或超时不退出，不强杀其他实例。
5. 辅助进程核实原 PID/启动时间并等待退出，取得更新锁和独占实例锁，再把旧目录重命名为 `previous`、新目录整体重命名到原路径。过程日志独立落盘；不逐文件合并、不修改 `%LOCALAPPDATA%/Screenshot` 下的用户配置、密钥、WebView 或恢复库。
6. 替换异常自动恢复旧目录；即使日志不能写入，也先尝试恢复目录。重启立即失败/提前退出则回滚；React 主动报告就绪才标记 committed。90 秒后仍运行但未就绪的进程不会被强杀，保留 awaiting-health 与回滚入口。
7. 设置可明确选择「回滚并重启」。旧版本或日志失效时保留所有目录并报告错误。事务目录带「恢复说明.txt」及独立工具；安装目录因断电处于两次重命名之间时，可关闭所有实例后运行其中的 `worker/Screenshot.exe --recover-update <事务目录>`。它根据实际目录和摘要恢复，重复恢复保持安全。

目录重命名的两步之间仍存在断电窗口，不能称整个安装切换是一次原子操作。恢复工具和旧目录提供可恢复性；无法承诺磁盘损坏或任意断电下绝不丢失元数据。辅助进程不提权、不终止用户进程；目录无写权限、空间不足、其他实例占用时失败关闭。

不能原地更新时，使用「解压到新目录」：选择上级目录，创建尚不存在的版本目录，先在 `.partial-<guid>` 中复制、校验，完成后整体改名。明确提示先保存并退出旧程序，再手动运行新目录的 Screenshot.exe；不会自动启动它。失败的 partial 目录可保留诊断，不覆盖既有目录。

旧版、故障版与恢复工具不自动删除，可能占用多个完整便携包空间；确认运行稳定后可人工清理对应事务目录。下一次更新只显示最近一次事务，旧事务仍在原处。用户数据目录不属于这类清理对象。
