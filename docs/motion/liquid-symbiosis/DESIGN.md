# 液态共生：全应用设计方案

设计版本 1.0.0 · 2026-10-22 · 状态：可审阅设计与独立原型

## 1. 已确认的方向

本方案承接本次讨论，不重新询问风格，也不提供与已选方向相竞争的三套方案。

用户已明确：截图的主操作需要具有独特动效；所有交互精致、自然且统一；总体满意原有视觉与运动风格；更喜欢有生命力、主动回应的液态界面；按钮本身向指针轻微靠近并形变；工具轨以整体方式响应，每个按钮又有独立感知；选择 **B：明确交互时可短暂融合、分离的液态共生**。

因此，目标不是增加更多弹跳或光效，而是建立一套连续的因果关系：

**靠近 → 感知 → 局部迎向 → 邻近传导 → 按压 → 状态转移 → 回流稳定。**

Soft Clay 决定表面的触感；Liquid Symbiosis 决定表面如何响应；光影只帮助读懂形体，不独立表演。界面应像同一块有表面张力的柔软材料，形成多个各自可操作的凸起。

## 2. 不改变的产品约束

保留现有 Windows-first .NET / WPF / WebView2 / React 架构。热键或托盘启动，框选后原位编辑，“完成”复制成功并通过当前文档身份确认后收起、清空本次编辑。自动保存保持关闭；手动项目及旧历史记录仍存在；不恢复“继续编辑”成功提示。

“收起编辑、保留文档”与“完成并结束本次编辑”必须区分。Esc 是按上下文逐层返回，不是无条件退出。OCR、翻译与服务测试只在明确请求后运行；不因悬停、打开面板或漂亮的入场自动发起任务。

不新增马赛克、序号、画笔、贴图桌面等仅在旧 Demo 示意但不属于当前工具轨的功能。原型使用现有矩形、箭头、文字、高亮、实色遮盖等功能名。现有文字重排项目读取与渲染兼容仍保留，不重新把已精简的文字卡片入口放回主导航。

本方案不是生产开发授权，不改应用行为，不合并、不发布、不启动真实桌面验收。

## 3. 视觉方向：保持材质，重组运动

### 3.1 颜色与材质

沿用当前应用的深暖灰 Soft Clay，而不是把旧 G 动效演示里的浅泥色直接覆盖应用：正文 `#f5f5f7`，次级文字 `#b7b5b3`，输入井 `#181719`，主操作蓝 `#3b82f6`，表面由 `#4a4642` 过渡到 `#2a2724`。实际生产来源为 `design/soft-clay.tokens.json`。

工具轨采用四段曲面；大浮卡采用双段暖灰面；顶部内高光与底部阴影表达厚度。普通控件、输入井、选中工具、危险操作拥有明确角色，不用同一种蓝色表达所有状态。

蓝色代表明确选择或主操作。指针临近只改变中性材质和轻微亮度，**不能让悬停看起来像已经切换工具**。成功、失败与警告同时配文字，不只换颜色。

不增加玻璃透明度、霓虹描边、常驻发光线、全局颜色漂移。不能用明亮高光覆盖文字来换取“液态感”。主图和标注本身保持原来的颜色，界面材质不写入截图输出。

### 3.2 字体、尺寸与轮廓

使用现有系统中文字体栈。正文 13 DIP、标签 12 DIP、面板标题 15 DIP、常规控件 40 DIP、紧凑工具 36 DIP。控件与面板以 12 DIP 圆角为基准。

本方案提出工具轨外壳 22 DIP 圆角，作为连续液态承托面的局部设计候选，而不是全局圆角迁移。按钮本身仍是 12 DIP。选区保持 1.25 DIP 精确边界和 12 DIP 视觉手柄，不使用旧 Demo 的 7px 厚边来模糊裁剪边界。

图标、标签与输入文字不参与拉伸。按钮的表面层可以变形，图标只做较小同向平移；两层不同处理，避免把“材质柔软”变成“文字变形”。

### 3.3 三套坐标不可混用

1. **业务坐标**：原图物理像素、真实选区、标注几何、导出尺寸。
2. **布局坐标**：WPF DIP / CSS px，按钮槽位、浮卡与工具轨位置。
3. **表现坐标**：按钮表面偏移、液桥与高光，仅用于临时绘制。

业务几何和命中盒不能因为表现坐标变化而更新。液桥、阴影、鼓起、高光都不接收指针。用户点击的是稳定的按钮槽位，不是在追逐一团会移动的液体。

## 4. 主工具轨的群体行为

### 4.1 不是一排独立 hover

工具轨有三层联动：目标按钮主动迎向指针；同组相邻按钮递减响应；底座产生很小的承托形变。远处按钮不参与，完成、取消、危险操作不会被邻居无条件牵动。

按钮可以感知，但不能抢先执行。界面可以迎向用户，但不能把指针吸走，也不能改变用户输入速度。实际鼠标位置不变，不制造系统级磁吸。

### 4.2 临近时的视觉过程

指针还在按钮外时，最接近的一侧开始被牵引。靠近目标后，目标表面发生轻微非对称形变；相邻按钮只跟随一小部分，不变成同等强度的放大。底座在目标下方略微隆起，仿佛承接张力，而不是整条轨道跳起来。

从 A 移向 B，A 从当前形态回流，B 同时迎向。快速反向时从当前速度与位置重新计算，不排队播放先前的动画。

### 4.3 B 方案：有条件的融合

相邻按钮平时各自独立。指针跨越同组相邻按钮、明确切换同组工具、或从按钮展开相邻浮卡时，可短暂出现液桥。液桥仅表达关系，不是新的可点击区域。

约束：最多一条按钮间液桥；不能跨功能分组；不能跨不可见的滚动内容；不能连接禁用、删除、完成或取消；不为每次微小 pointermove 生成新桥；稳定悬停后消失。浮卡与按钮距离过大、翻转摆放或手动脱离后，不画横跨画面的长液丝，改为带来源方向的展开。

### 4.4 明确点击的语义

按下时，受力按钮下陷、两侧轻微扩展；邻近传导仅是一点压力反馈。指针按下后冻结吸引目标，不让按钮在拖动期间继续逃逸。真正的 click 到达时立即执行工具选择，不等待恢复。

只有工具选择才让蓝色激活材质迁移。美化、OCR、更多是“打开面板”；翻译图片是“发起任务”；完成是“提交输出”；这些不应都表现为一个持续选中的蓝色工具。

### 4.5 停止也是动效语言的一部分

没有交互时不循环呼吸、不周期扫光、不持续变形。只有正在执行的任务需要持续等待指示，而且保留取消出口。帧循环在停稳后休眠。所谓生命感来自对意图的响应，而不是无意义的背景活动。

## 5. 截图主流程

### 5.1 唤起和框选

热键或托盘唤起后，背景遮罩以短淡入建立工作上下文；没有全桌面缩放、视差或模糊。原图不移动，用户始终能看清要截取的对象。

框选、八方向调整、移动与键盘微调的真实边界严格跟手。尺寸标签可以有极轻的外观响应，但数值即时更新，不能用慢滚轮掩盖真实像素。触摸和笔输入不伪造鼠标预感知。

窗口吸附时只有目标轮廓的确认反馈；磁吸视觉不能修改底层窗口命中决策。当前屏幕、指定屏幕、全桌面直接进入合法的编辑状态，不强行播放不存在的拖框过程。

### 5.2 松手交接

正式流程由原生捕获、解码、网页静态布局、宿主合成帧确认等事件决定。工具轨只能在当前捕获真正可呈现且可操作时进入，不在隐藏等待期提前播完。

工具轨沿真实放置方向展开，完成按钮优先保持可辨认。工具逻辑就绪立即可点；外观可以继续落定。取消“弹簧达到 0.85 才允许动作”的普遍业务规则，避免动画额外锁住已就绪的功能。

原型演示的是网页交接表象，不能据此认定 Windows 合成没有闪烁。

### 5.3 标注与对象编辑

选择工具只进入待命。矩形、箭头、高亮、遮盖在实际按下和拖动后产生草稿，松手有效才提交一次历史；误触、Esc、pointercancel 不生成空对象。

落笔位置不使用追尾弹簧。视觉反馈位于笔尖之外或工具表面；箭头端点、实色遮盖边界、文字光标与选区保持精确。选中对象后打开对应属性；非文字不出现可用字号操作。

对象拖动、端点调整、键盘微调直接跟手。删除只影响当前对象；撤销与重做恢复内容状态，不重播整套截图入场，不清空其他工具位置。

### 5.4 完成

区分“点击了完成”和“确实完成”。进入生成/复制中后给出立即响应，保护当前输出版本。成功确认之前不吸走原图、不显示“已复制”、不隐藏编辑器。

PNG 复制成功、文档/修订/捕获身份仍匹配且宿主同意关闭后，才让工具轨张力向完成按钮短暂汇聚、选区收束、浮卡回收。确认后退出的动画是一个短尾声，不是额外的工作流程。

失败保留原图、标注、面板和工具位置。过期结果拒绝隐藏新截图。文件对话框取消不表现为错误或成功。复制已成功但退出确认失效时应说明“已复制，但当前编辑未结束”，不能冒充“复制失败”。

### 5.5 收起与 Esc

收起保留文档，用低强度回流离场，不使用“本次任务完成”的庆祝反馈。Esc 依次归还当前占用：输入法组合由输入系统处理；活动手势取消；输入结束；最上层弹层/模态/阅读窗关闭；异步任务取消；对象选择或待命工具解除；属性面板关闭；最后才收起截图。

具体优先级遵循事件所有者，局部已经处理的 Esc 不再向全局传播。不能在关闭颜色弹层时顺便丢掉截图。

## 6. 编辑与内容处理

### 6.1 美化

预设是同一文档的样式切换，不新建截图。预设按钮轻微受力，预览立即应用；外框、背景、圆角和阴影可短过渡，截图正文不做弹性形变。滑杆的滑块、数值和文档状态同步更新，松手只记一条调整历史。

原样、细调、颜色、样式保存/删除/应用均保留。颜色弹层中草稿与提交分离；Escape 或外部关闭不能悄悄提交草稿。Demo 的颜色输入与下拉仍用浏览器控件，生产接入继续使用已有 ColorField/Select，不替换为浏览器系统弹窗。

### 6.2 OCR 与文字翻译

打开面板不执行识别。明确点击后进入“请求中”，轻量状态条显示阶段，输入的已有结果保留。空结果说明没有新增内容，部分失败保留成功块，重试应针对失败块；Demo 只模拟补全反馈，不声称拥有真实分块调度。

本地/云端差异、模型不可用、服务未配置、超时、网络错误、限流及取消都有明确出口。等待图形不冒充精确百分比；只有实际可度量任务才展示进度。原型中的百分比全部标注为模拟。

源框选择给局部明确反馈；校对文字不回弹、不抖动。原文变化后译文标记过期，不立即清空人工校对内容。请求戳同时保护文档身份、修订、服务配置与语言，迟到结果不跨文档回填。

### 6.3 图片原位翻译

识别、翻译、排版是同一次显式任务的阶段，而非三个独立窗口。保留源图，在独立图层回填译文，一次撤销。原位排版不借助夸张液态变形表现“智能”，只在真正提交成功后进行短淡入。

空间不足时明确出现阅读入口，不静默把小字扩大遮住其他内容。原图、文字框与译文的导出规则不由动效修改。需要背景修复、旋转文本和复杂排版等能力时不得用视觉原型冒充已实现。

### 6.4 阅读窗口

阅读入口出现时保留完成按钮位置，不让工具轨整体跳动。窗口可拖动、调整尺寸、恢复默认位置；关闭再打开在当前会话保留位置。宽窗口原译双栏，窄窗口上下对照。

阅读正文是系统中最安静的层：没有液态拉伸、逐字弹出和悬停追光。字号 16–28，默认18；阅读与对照切换强调连续版面与稳定滚动锚点。

无法在截图外容纳时进入临时阅读视图：保留画布和编辑文档，只隐藏或停用背后的操作层；关闭后回到同一截图。文字复制不改变原图，阅读字号不参与导出。

## 7. 文件、历史与系统窗口

### 7.1 文件与项目

打开图片、拖入、粘贴和打开项目进入同一编辑内核。无冻结桌面的文件使用中性背景，不伪造捕获坐标。导入中给局部等待，解码失败保留当前文档；取消文件选择不产生假成功。

手动项目保存成功才给“已保存”；完成复制 PNG 不等于保存项目。已有历史记录可查看、恢复、删除和确认批量清理；不建立新的自动保存或永久图库语义。

### 7.2 托盘、设置、条款与更新

托盘菜单是同材质的轻浮卡。来源能可靠定位才做短来源展开；系统隐藏托盘、坐标不可用时使用淡入，不虚构液桥位置。托盘打开设置不恢复历史截图。

设置保留截图与快捷键、识别与翻译、应用更新三页。字段、密码、下拉、复选框和滚动都保持稳定。服务测试仅说明当前响应，不暗示模型质量或全部能力通过。

更新中区分检查、候选、下载、取消、完整性校验、等待交接、安装失败、回滚；动画不能跨越安全门禁。首次条款默认未同意，关闭/拒绝走安全分支，不用动效诱导接受。

## 8. 组件规则

| 类别 | 连续感 | 运动边界 |
|---|---|---|
| 主工具按钮 | 感知、迎向、按压、回流、同组液桥 | 不移动布局/命中盒；文字不形变 |
| 预设与普通按钮 | 短受力、底色连续变化 | 不从远处迎向，不影响邻近表单 |
| 输入框与文字井 | 焦点材质平缓变化 | 光标、基线与文本不移动 |
| 下拉/菜单 | 从触发器方向展开、选中项就近反馈 | 键盘焦点清晰，关闭归还触发器 |
| 滑杆/数字 | 触点受力，数值即时 | 不缓动实际值，不改变步进语义 |
| 复选框/开关 | 明确选中转换 | 不在旁边传播液态选中态 |
| 折叠区 | 容器高度短过渡，内容稍后淡入 | 尊重滚动锚点与快速反向 |
| 提示/错误 | 来源明确、短进入 | 错误不自动消失；不靠闪烁强调 |
| 滚动条 | 活动显示、空闲淡出 | 拖动期间可见，隐藏后不抢命中 |
| 确认框 | 低强度容器进入 | 焦点围栏，危险动作需明确确认 |

## 9. 布局和极端条件

主工具轨允许动态按钮；“完成”位于稳定末端，低宽度时滚动普通工具区而不是把完成挤出屏幕。只有可见、同组、距离允许的按钮参与液桥。滚动、尺寸和 DPI 改变后重建稳定矩形缓存。

属性卡优先使用截图外空间；不足时向上、向下或侧面翻转，保留完成入口；再不足则卡片内部滚动。不能以让卡片盖住完成按钮解决拥挤。用户手动拖动后不在每次重渲染回跳。

跨屏与混合 DPI 中先确定工作区和逻辑尺度，再绘制装饰。显示缩放不修改导出像素。真实多屏、Windows 焦点与中文 IME 均需要独立验收，不由浏览器宽度测试代替。

## 10. 设计完成的定义

完整方案意味着现有应用的主要界面、组件、状态和异常都有去向，而不是每个原生能力都被重新实现进 HTML。可操作程度和验证边界详见 COVERAGE.md。

原型允许审阅视觉、运动与局部交互；生产改造必须先核对本轮应用基线，按 IMPLEMENTATION.md 接入原有模型、桥接与状态保护。**没有新增一套会覆盖生产功能的“演示版工作台”。**
