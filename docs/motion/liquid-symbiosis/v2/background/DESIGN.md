# 背景轻移：把初稿的空间感接回 v2

2026-10-22 · 背景设计 0.1 · Demo 与正式宿主共享参数

## 设计意图

让整个截图环境像一块柔软、有重量的底板，轻轻承接鼠标的方向。用户注视的选区保持清晰稳定；视野边缘能感到背景发生了一点变化，停住后自然安定。主角仍是 v2 的截图内容和工具轨。

这份方案针对「选区外的冻结桌面背景」，不改变导出图片中的美化背景，也不让选区内容与标注整体追着鼠标漂移。

## 从初稿保留什么

| 来源 | 原表现 | 本方案 |
|---|---|---|
| `../../../index.html` 的 G 融合桌面层 | 光标归一化，低频弹簧；背景反向 ±10 / ±8px | 保留低频、有重量的追随；改为同向 ±6 / ±4px，贴合本轮“跟随”意图 |
| 同稿 PX / VG 双层响应 | 桌面 k90/c19；暗角 k140/c22，中心可随指针大范围移动 | 桌面 k100/c22；暗角 k65/c19，中心只偏移 ±12 / ±8px，稍慢一层 |
| 同稿启动退景 | 缩小至 .975、模糊 1.2px、暗角收束 | 只保留背景 3px 的短归位与薄暗角显现；不缩放、不模糊截图 |
| `../DESIGN.md` 与 `../MOTION-SPEC.md` | v2 固定命中区、内容坐标独立、静止休眠、无全屏视差 | 延续坐标隔离；本候选明确试验有限背景视差，未改写或替代 v2 已确认规范 |

没有沿用原稿的长距离追光、循环边框扫光、桌面缩放以及完成时再次模糊。背景的视觉反馈弱于工具按钮，避免和 v2 的局部迎向、液桥、按压回弹竞争。

## 图层关系

从后向前：合成冻结桌面的显示副本 → 固定遮罩与薄暗角 → 静止截图像素 → v2 框线/手柄 → v2 工具轨和浮卡。

- **桌面显示副本**是唯一移动的位图层。当前 Demo 的原始桌面位图不被改写。
- **薄暗角**是第二个低强度装饰层，附属于原 v2 遮罩，自动避开选区；没有沿指针打出一束强光。
- **截图和标注**继续由原 v2 文档绘制，背景位移不进入 crop、历史、项目、PNG 或指针命中计算。
- **工具轨**保留 v2 自己的表面响应，不接受背景位移。截图位置、框线、命中槽位都保持原坐标。

显示副本四周复制 16px 的边缘像素；零位移时中心图像与原桌面一致，移动时不会露出透明缝，也无需通过缩放填边。只在源图或舞台尺寸改变时重建显示副本。

## 参数与跟随方式

全部位移单位为 CSS px，不是 Windows 物理像素。弹簧质量为 1。

| 参数 | 默认 | 设计作用 |
|---|---|---|
| 桌面 X / Y | ±6 / ±4px | 水平略强，避免上下浮动像画面抖动 |
| 桌面 k / c | 100 / 22 | 轻柔跟手，阻尼足够，不刻意回弹 |
| 暗角 X / Y | ±12 / ±8px | 只是大面积渐变中心的偏移，不等于图像二次位移 |
| 暗角 k / c | 65 / 19 | 比桌面更慢，提供极弱的深度差 |
| 启动 Y | 3 → 0px | 桌面短归位；暗角同时由 0 → 1 显现 |
| 启动 k / c | 150 / 25 | 约半秒感知上的落定，最终休眠取决于阈值 |
| 幅度调节 | 50%–125%，默认 100% | 桌面最大 ±7.5 / ±5px；与启动 3px 短偏移独立 |
| 图像边缘扩展 | 16px | 大于最大跟随和启动偏移之和 |

指针相对舞台中心归一化：`nx = clamp(2 × localX / width − 1, −1, 1)`，Y 同理。桌面目标为 `(nx × 6, ny × 4) × gain`；暗角目标为 `(nx × 12, ny × 8) × gain`。正方向与指针相同。

直接复用 v2 `Spring` 的半隐式欧拉积分：单步 ≤1/120s，单帧累计 ≤50ms；位置误差 <0.003、速度 <0.018 后归位，连续五个静止帧后停止背景调度。快速反向只改变目标值，继续使用当前位移和速度。

停止移动指针后，背景停在当前指针对应的微偏位置；离开舞台才回到中心。不会持续呼吸、绕圈、晃动或自动重播。

## 状态与中断

| 状态 / 事件 | 背景表现 |
|---|---|
| 打开 Demo / 重播启动 | 单次 3px 归位与薄暗角显现；v2 工具轨入场保持原样 |
| 移动指针 | 同向、有阻尼的轻跟随 |
| 快速反向 | 保留当前位置与速度，不排队播放 |
| 指针停住 | 到达当前目标后休眠 |
| 指针离开舞台 | 平滑回到中心 |
| 按住绘制、拖动、调整大小或操作工具 | 背景冻结在当前可见姿态；启动中也不突然跳到终点 |
| 松开 / 丢失指针捕获 | 从冻结姿态继续趋近最新目标 |
| pointercancel | 释放冻结，向中心归位 |
| 新建截图 / 正在框选 | 立即回到原始对齐位置，在整个框选阶段停用跟随；先保证坐标与源图一致 |
| 阅读、模态、任务处理中 | 平滑回到中心，专注内容或任务 |
| 模拟完成 / 收起 | 随既有 v2 退出期间归正，隐藏状态立即清零并休眠 |
| 页面隐藏 / 失焦 | 清除目标和速度，直接归零；恢复后等新输入，不重放旧轨迹 |
| 系统或手动减少动态、低开销、粗指针 | 停止背景空间运动，保留静态截图、遮罩和业务状态 |
| 调整窗口 / 更换合成桌面 | 重建显示副本，清除旧尺寸下的目标，不修改文档 |

静态对照与关闭跟手立即归零，便于判断差异。减少动态以系统偏好为最高优先级，页面内不能关闭系统要求。入场进行中重复点击重播不会重新归零闪烁。

## Demo 与正式接入

本包复用原 v2 HTML、CSS、`engine.js`、`app.js` 与材质 Token，构建时加入候选背景扩展；所有基准文件保持原样。背景扩展的调度器独立于 v2 工具调度器，只有背景未停稳时请求帧；正式实现时应接入宿主现有的可见性与逐帧调度。

生产接入已保留以下边界；实机验证仍需后续授权：

1. 原生冻结桌面、截图裁剪与屏幕权限留在 WPF 宿主；编辑器只知道其现有裁剪图，不接收整个桌面。
2. 背景 RenderTransform 不参与物理像素映射、捕获选区和导出；原生框选与 handoff 期间保持完全对齐。
3. 宿主隐藏、捕获代次、WebView ready/painted 和合成帧门保持原来的顺序；背景不能为交接增加可见等待。
4. 混合 DPI、多屏负坐标、真实显卡开销与系统减少动态需在得到桌面验证授权后单独验收。

本轮的浏览器结果只能支持这个候选背景方案，不证明 WPF/WebView2 的视觉质量或 60/120/144Hz 性能已达标。
