# 0.4.1 后台质量报告

本批只使用合成图、临时SQLite和本测试创建的进程。没有捕获桌面、枚举用户窗口、操作真实热键/剪贴板/焦点/对话框/IME，没有用户密钥或真实AI请求，也没有真实断电。0.3.0/0.4.0制品保留，0.4.1仅构建交付，未发布Release。

## 大图测量

Windows 10.0.26300.0 x64；.NET SDK10.0.102；独立无头Edge 155.0.4283.62；软件渲染（--disable-gpu）。相同基准脚本分别读取保留0.4.0网页和新构建。每项3次、表中为中位数；负载前生成固定色块PNG，不能代表照片压缩比或真实捕获耗时。导出时钟在页面内从点击处理至模拟桥接发送，排除自动化驱动及原生IPC；导入/预览的原始日志仍含驱动等待，不用于CPU加速结论。

| 输入像素 | PNG字节 | 0.4.0美化导出ms | 0.4.1美化导出ms | 0.4.1原样导出ms |
|---|---:|---:|---:|---:|
| 1920×1080 | 55,273 | 30.3 | 21.1 | 1.4 |
| 3840×2160 | 208,083 | 84.8 | 69.3 | 1.1 |
| 7680×4320 | 800,470 | 329.4 | 279.5 | 14.6 |

三种原样PNG均逐字节相等；美化尺寸含96px留白；8K美化2×超过4000万像素上限时，明确拒绝且不发送复制请求。无标注导出直接编码目标底图，跳过另一套Fabric画布；取消、替换及卸载的私有画布显式释放背板，带标注仍走同一Fabric模型。

独立浏览器在负载前报告的PID集合，每50ms采样：私有提交内存峰值合计 1.586→0.903 GB；工作集合计 3.419→2.720 GB。工作集包含共享页重复计数，PID集合不覆盖之后才出现的进程，采样会漏掉瞬时峰值，也不等同GPU显存。页面GC后JS堆和重置小图后的指标均保留原始JSON；不把GC或关闭文档等同于OS立即归还内存。

## 存储基准与修复

3200×1800固定噪声PNG，18,226,512字节；排除PNG生成和预热，持有准备好的JsonElement，3次保存/加载且原图去重为1份。旧版用当前同一测试驱动在隔离目录加载0.4.0原始Storage DLL（先核对旧包SHA256），新旧输入及测量工具相同。

|---|---:|---:|
| 保存中位数ms | 101.2 | 60.6 |
| 加载中位数ms | 118.0 | 30.2 |
| 三轮累计托管分配GB | 2.677 | 1.010 |

保存先流式去掉dataUrl，再有界解析元数据；Base64解码不复制整图子串。恢复以自身编码的ASCII Base64写JSON，避免大字符串最坏转义缓冲，不把外部字符串作为裸JSON写入。保留未知元数据、原图字节和Unicode/HTML样式纯文本；拒绝重名字段及超额元数据。已初始化库不再每次重复写schema版本，真实加载的写保留锁仍保护跨实例资产回收。分配计数含测试校验与采样器，不等同存活堆；进程私有提交也不是物理RAM。3次样本不作跨机器性能保证。

## 故障注入

四阶段均通过生产SaveAsync及专用临时库，测试只按自身Process对象终止自己启动的子进程。资产提交前阶段使用仅该临时库的慢SQL触发器；WAL溢写阶段用未提交事务和小页缓存。未使用生产故障注入后门。

| 终止阶段 | 重开结果 |
|---|---|
| 资产部分写入，确实观察到未写完临时文件 | 修订1及旧PNG完整，后续保存清理部分文件 |
| 新资产已落盘、文档尚未提交 | 修订1及旧PNG完整，孤立新资产可清理 |
| 未提交WAL页已溢写 | 修订1完整，未提交行不出现 |
| 保存已返回提交成功 | 修订2/PNG/译文校对完整保留 |

既检查幸存实例的生产LoadAsync，也用全新验证进程进行PRAGMA integrity_check、修订/图像/翻译块及孤立资产清理检查，保留无关合成哨兵文件。初轮同进程探针及生产LoadAsync曾得到IOERR_TRUNCATE，冷进程恢复正常；减少重复schema写入并增加仅1546的有界幂等读重开后，四阶段完整重跑通过。相同旧DLL对照也有通过记录，尚不能归因于单一底层原因。保留失败日志，不把失败探针当成功证据。此结果不证明真实断电、磁盘/硬件损坏或持久化设备缓存行为。

## 原生与许可

同版本OpenCvSharp官方win.slim运行时已通过15项算法/16项含固定CPU模型推理；实际DLL SHA256与NuGet包一致。仅使用core/imgproc/imgcodecs等OCR路径，不带未使用FFmpeg插件。slim的GetBuildInformation仍是上游共用静态库构建说明，不能把其中全部模块当作实际链接模块，也不能据此声称nonfree/IPP全部移除。

新native-audit逐个解析包内PE、按文件SHA256对应NuGet/框架pack或本项目来源，并列出直接/延迟导入。Windows SDK目标框架程序集原先未进入库清单，现单列来源。外部Visual C++运行时由诊断按目标机器System32重新检查文件和版本，不能沿用构建机present标志；不加载DLL、不自动安装。文件存在仍不证明导出符号、架构或干净机器运行。

补入固定上游OpenEXR/OpenJPEG/Protobuf/FlatBuffers、zlib、libjpeg-turbo/IJG、libpng、libwebp、TIFF、LZMA、ITT、OpenCL，以及固定IPP制品的原始EULA/third-party-programs。原始字节、来源URL及SHA256在licenses/native-license-sources.json；Git禁止这些文件行尾转换，发布时逐项核对。详细缺项见RELEASE-LICENSE-REVIEW.md：vendor精确静态链接闭包、IPP再分发条款、SDK文件映射、stackback许可正文仍未正式关闭；不能把清单完整扫描等同于法律结论。

## 交付与剩余边界

后台代码/质量证据可交付；正式公共分发、真实Windows捕获/透明合成/混合DPI/窗口边界/热键/剪贴板/拖入/IME、真实服务商及干净机器仍未验收。桌面动作需要用户解除暂停；真实AI需明确允许的服务配置/费用边界；安装器、签名、更新、卸载、额外字体、ARM64继续待决定。大图资产ID通道尚未替代Base64跨桥传输，长时间连续捕获、目标硬件/GPU峰值等仍不能由本次短基准代替。

完整原始证据在被忽略的artifacts/qa/quality/，CI另上传同名质量证据。运行方式：先verify.ps1构建，再配置独立Playwright模块执行scripts/quality.ps1；所有临时根均为Screenshot-quality-随机ID。

Windows中断写入后观测到的SQLite IOERR_TRUNCATE（1546）仅对Load/List/Usage等幂等读取有限重开两次，额外等待共不超过75ms且可取消；写入、缺失资产、权限错误和损坏错误不自动重试，失败仍明确报告，不删除数据库/WAL/SHM。该异常的具体环境成因尚未确定；有旧版对照偶发通过/失败，不能宣称已证明某一底层原因。

最终本机验证：编辑器51项、原生边界190项、模拟AI18项、SQLite56项、OCR算法15项/含固定模型推理16项、离屏24场景、4个真实子进程中断阶段全部通过；.NET构建0警告/0错误，Vite保留约603kB分包提示。新包491个PE文件均有哈希来源，188项CycloneDX组件；保守原生静态组件另见14项人工清单，不冒充精确vendor链接映射。

新包仍直接依赖4个Visual C++运行时DLL及mfplat/mf/mfreadwrite 3个Windows Media Foundation DLL；本机文件存在且版本可读，不等同干净机兼容性验收，也不代表slim移除了全部媒体依赖。
