# 0.4.7 更新功能审查

本次为提交前代码/模拟审查，不是实机安装验收。基于 v0.4.6 创建独立功能分支，维持 WPF/WebView2/React/TypeScript 架构，未新增依赖。

已发现并修复：

1. 设置请求本身持续等待，若笼统禁止 busy 会永远无法安装。改为命名设置操作特例，其他本地/AI 任务仍阻止退出，增加真实 React + 内存宿主无头联调。
2. 同修订重复保存会被恢复库拒绝。更新前使用独立恢复身份，保存失败阻止退出；初始空文档不消耗恢复容量。
3. 故障回滚若先写日志，磁盘满会妨碍恢复。改为日志尽力写入，目录恢复优先，文件锁模拟日志不可写时旧版仍可恢复。
4. CreateNew 下载失败时不得删除已有目标；只清理本次确实创建的部分文件，并覆盖传输中取消、重试和既有文件保护。
5. 辅助进程超时后不能在用户稍后普通退出时意外安装。增加明确的交接确认/取消文件，只有确认交接且原 PID/启动时间吻合并退出后才执行。
6. 不能只比较 API 版本。执行阶段再次核对包清单摘要、当前安装摘要和 SBOM 版本，拒绝损坏、陈旧候选和降级。
7. 并排解压也不得形成可误用的半包。使用独立 partial 目录，全部验证成功后才改名为最终目录。

审查结论：本分支可提交 PR 供评审，不能据此发布或宣称真实自动更新已验收。私有远程获取的登录代码已按后续明确授权实现；默认 Client ID 为空，明确未配置。真实 App 注册/安装、Client ID 配置和真实 OAuth/私有下载仍待发布者后续操作与实机验收。当前 ZIP 没有独立发布者签名；信任边界和恢复限制见 [UPDATES.md](UPDATES.md)。真实安装/回滚/多实例交接、断电、权限、杀毒软件、首次条款确认与重启必须另行获准后验收。

无自动合并、tag、Release、仓库权限或产物公开操作。


## GitHub App 登录增量审查

本增量继续 PR #1，不改变 0.4.7 开发版本、不发布。只使用虚构设备码/令牌的内存 HTTP 与可推进时钟，无真实 OAuth 请求。

- 默认未配置时不联网；专用公开 Client ID 通过构建注入，没有 secret/token/private key 配置入口。主窗口持有一次进程会话；关闭设置取消操作，退出/应用关闭清除引用。没有任何认证桥接、磁盘保存或开发机凭据读取。
- 固定官方 HTTPS OAuth、仓库 ID/full_name、账号与 Release Contents 读取校验；授权页明确告知源码读取权限。对服务端不能强制缩减的 App 安装权限，要求发布者按最小设置配置；不声称客户端能约束已被错误配置的服务端 App。
- 轮询 pending/slow_down、设备码到期、取消、拒绝、超时、限流有受控错误；拒绝 OAuth 重定向，服务端正文不进入错误/日志。刷新串行化，旧令牌 401 不清除新会话；迟到授权/刷新不能复活已退出会话。
- 私有资产 API 每请求授权，CDN 每跳剥离认证/Cookie；退出中止下载并作废候选。下载/检查仍保留官方 SHA、完整包清单与降级保护，登录不替代发布者签名。
- 审查修复：坏刷新 JSON 清除会话并隐藏原始错误；更新元数据 JSON/类型错误安全化；下载网络错误不泄漏签名 URL；清理临时目录异常仍释放门锁和作废候选，避免异步 UI 事件未处理异常。

无新增代码审查阻塞。尚不能宣称真实设备码登录、GitHub App 权限配置、WPF 可读性/键盘或真实安装验收通过。配置步骤与唯一需提供的非秘密 Client ID 见 [GITHUB-APP-SETUP.md](GITHUB-APP-SETUP.md)。
